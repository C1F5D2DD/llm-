# AutoXXT

学习通（超星 chaoxing）网页版自动化。

**网页版 + Edge 调试协议（CDP）**，全程后台：不移动真实鼠标、不需要窗口可见或获得焦点，
你可以一边挂着它一边打游戏、干别的。

## 文件

| 文件 | 作用 |
|---|---|
| `pageCapture.py` | 截图（CDP），图上叠坐标网格 |
| `window_control.py` | 输入（CDP）：点击 / 拖动 / 滚动 / 打字 / 按键，还能挪动浏览器窗口 |
| `brain.py` | 决策：把截图交给多模态模型，拿回一个动作 |
| `run.py` | 界面：左边实时画面 + 控制面板，右边对话区 |

## 快速开始

```bash
conda activate autoxxt
pip install -r requirements.txt
python run.py
```

`run.py` 会启动带调试端口的 Edge（登录态存在 `edge/`，只需登录一次）。

然后：左边填好 `接口地址 / 密钥 / 模型`，点「保存配置」，右边发一句话就行。
比如「帮我打开 Python 那门课」。

模型会自己连续跑：每一步的思考、动作、结果都会滚进对话历史，左边画面同步刷新。
跑的过程中你随时可以：

- **点停止** —— 当前这步执行完就停（网络请求没法打断，但它返回后不会再执行）
- **发消息插话** —— 排队带到下一步，不会丢
- **点清空** —— 清空对话历史和模型上下文

一个回合最多跑 50 步（`run.py` 里的 `MAX_STEPS`），防止模型停不下来。

## 对话区怎么用

```
你：帮我打开 Python 那门课
AI  页面有课程卡片，点开 Python 语言程序设计
  ▸ 点击 (450, 320)
  ✓ 已点击 (450, 320)（地址变了 -> ...）
AI  进了课程页，点第一节
  ▸ 点击 (300, 180)
  ✓ 已点击 (330, 180)
AI  视频在播放，等一会儿
  ▸ 等待 30s
  ✓ 已等待 30s
■ 完成：已在第一节视频页
```

前缀含义：`AI`=模型的想法，`▸`=要执行的动作，`✓`=执行结果，`■`=回合结束，
`✗`=出错，`?`=模型求助，`·`=提示。

## 模型是怎么决定下一步的

每步把**两张截图**发给模型：上一屏 + 当前屏。**变没变由模型自己对比**——
程序不替它下"页面有没有变化"的结论。

这是踩坑换来的：程序能查的只有地址、滚动位置、标签页数这几项，而页面内部滚动、
跨域 iframe 里的滚动、弹窗浮现、按钮变灰它一概看不见。早先程序会据此断言
"页面没有任何变化"，把成功的动作报成失败，模型就反复重试同一个动作直到撞上限。
现在程序只报原始事实（`run.py` 的 `_facts()`），并明确告诉模型"以你看到的两张图为准"。

`page_info()` 会把页面大小、滚动位置等事实一起给模型，但它查不到时**会直说查不到**
（比如内容在跨域 iframe 里），绝不假装"页面只有一屏"。

## 坐标约定

截图上叠了一层半透明红色网格，数字就是那个位置的坐标（页面像素）。
模型读到多少就能填多少，喂给 `wc.click()` 就行——**不用做任何加减**。

网格是叠在图上而非画在边上：早先用刻度带，模型看图估坐标时总会多算一个带子的宽度，
实测偏 50 像素点不中。

## 作为库使用

```python
import pageCapture as cap
import window_control as wc
import brain

wc.init(pid)                 # 输入通道
cap.init(pid)                # 截图通道（内部起后台抓帧线程）
brain.init(base_url=..., api_key=..., model=...)

img = cap.get_frame()        # 最新一帧（带网格）
d = brain.decide(img, goal="进入我的课程列表", page=wc.page_info())
wc.click(d.action["x"], d.action["y"])
brain.note_result("已点击 (400, 300)")     # 把结果告诉模型，否则它会重复同一个动作

wc.type_text("要输入的内容")     # 在当前焦点输入（支持中文）
wc.press_key("Enter")         # 按键，支持组合键，比如 Control+a 全选
```

`cap.get_frame()` 几乎不耗时——后台线程一直在抓，它只是把现成的帧给你。
`cap.has_frame()` 可以先问有没有帧，避免等首帧时阻塞（界面循环该用这个）。

## 常见问题

**连不上 9222 端口？**
Edge 必须带 `--remote-debugging-port` 启动，并且要用**独立的 `--user-data-dir`**——
普通 Edge 已经在跑时，带参数再启动只会把标签页丢给旧实例然后退出，端口根本不开。
`run.py` 已经处理好这两点；手动启动是：

```bash
"C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" ^
  --remote-debugging-port=9222 --user-data-dir="edge" https://www.bilibili.com
```

**为什么用 CDP 而不是 Win32 截图？**
Win32 `PrintWindow` 快（15-56ms），但**要求窗口可见**——被遮挡或挪到屏幕外，
浏览器就停止渲染，截出来是黑的或卡在旧帧。CDP 截图慢一些（40-70ms），
但完全不依赖窗口可见性，这是能后台运行的前提。

注意：截图**仍然需要窗口处于"可见"状态**（没被最小化、没被挪到屏幕外）。
所以「显示浏览器窗口」开关关掉后画面就不再更新。要后台挂机，让窗口留在屏幕上就行——
模型和点击都不需要它在前台。
